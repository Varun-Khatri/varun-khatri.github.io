§ 01

Art Style — Expanded Definition

Missing from GDD. The current doc names references (Control, Ori) but never locks the pipeline rules that will govern every asset decision.

Stylised Realism — Locked Rules

  • Polygon budget per module: ≤ 80k tris (Quest 3 standalone, single module in view). Modules outside the camera frustum must be culled or unloaded.
  • Texture resolution: 1024×1024 max per surface material. No 2K or 4K on Quest standalone. PC VR may use 2K for hero surfaces only (portal frame, glove mesh).
  • Normal maps always. Every surface has a normal map — flat-shaded surfaces are not permitted. This is what gives the low-poly geometry the Control-esque weight.
  • No outlines / cel shading. Outlines are reserved exclusively for interactable object affordance (teal 2px outline on pullable objects). World geometry never has an outline pass.
  • Shadow strategy: Baked lightmaps for static geometry (LightmapGI). One real-time directional light per world state. No real-time shadows from dynamic objects on Quest standalone — shadow blob only (projected decal).
  • Vegetation: Billboard sprites for background foliage (Overgrown). No animated skeletal vegetation — use shader-driven vertex offset (wind shader, amplitude ≤ 0.08 m) on foreground vines only.
  • Debris / clutter: Max 12 unique prop meshes per module. Repeated via rotation + scale variation. No unique meshes for background decoration — instanced only.

Visual Hierarchy Rule

Three tiers of visual clarity, applied to every module:

  • Tier 1 — Player Path
    Brightest region of each module. Lit with fill light or emissive strip on floor edge. Player should always be able to see where to go without reading it.
  • Tier 2 — Interactable
    Amber glow (#D4A017) and teal outline. Pulls the eye away from Tier 1 just enough to notice but not enough to confuse navigation.
  • Tier 3 — World Dressing
    Darkest, lowest contrast. Silhouette-readable but never competing with Tier 1 or 2.
§ 02

Module Path Variation

Current issue: All module roots use rotation (0,0,0) and chain end-to-end on +Z only, creating a purely linear forward-only experience.

Path Direction Convention — Amended

Modules are no longer required to chain purely on +Z. Four valid exit directions are defined. A module declares its entry_dir and exit_dir as exported enum vars.

CodeWorld-space exitUse case
FWD+Z (forward)Default. Straight progression.
RIGHT+XBranch or detour to the right.
LEFT−XBranch or alternate route.
UP+YVertical climb or leap.

Module Root Rotation for Turns

To turn the path right, set the next module's root rotation.y = -90. Left: rotation.y = 90. The module's internal geometry does not change — only its root orientation in the level changes.

New Module Variants

Build these after core modules are locked.

A5
Corner Path — Right Turn

Safe walkway with a 90° bend right at the midpoint. Used to change direction without a puzzle. Variants: A5-S, A5-O.

EXIT → RIGHT
A6
Corner Path — Left Turn

Mirror of A5. Used for left-direction path changes. Same geometry, mirrored layout.

EXIT → LEFT
A7
Y-Fork

Path splits at Z midpoint. One branch valid, one dead-end teaser with a narrative prop. Dead end always has something worth finding — never a pure dead-end.

EXIT → FWD + branch
B5
Offset Gap — Lateral Jump

Gap crossed by jumping sideways (+X or −X), not forward. Next platform is offset to the side. Shifts the path laterally without a full corner module.

EXIT → RIGHT or LEFT
H5
Diagonal Climb

Vertical shaft where ledges alternate between LEFT and RIGHT walls — forcing lateral movement in addition to upward. Not a straight vertical chimney.

EXIT → UP
J
Junction / Hub Room

Small open room (8×8×4 m) with 2–3 exits on different walls. No puzzle. Contains a narrative prop. Spatial anchor the player may return through.

EXIT → FWD + RIGHT (± LEFT)

5-2 The Fold — X5 final set-piece

Single authored scene — not assembled from reusable prefabs. The only non-modular level in the game.

The player-choice moment (which Asha ceases to exist) must be implemented as a gesture choice, not a menu:

  • Two receiver pads appear — one Overgrown (amber), one Sterile (blue).
  • Player walks to one and places both hands on it (open palm Anchor on both hands simultaneously).
  • A 3-second hold seals the choice. No UI prompt.
  • Both Ashas speak simultaneously in spatial audio — one voice per ear. The player can take as long as they want.
  • The game never states a correct answer.
§ 06

Unanswered Design Questions — Now Locked

These questions were either not addressed in the GDD or only partially answered.
Does the player ever hold a physical prop to interact with the world, like the Dishonored timepiece?

Locked: No. The GDD answers this for world-switch (wrist-flip) and Pull (reach-through gesture). All input is body gesture — no held prop, no equip, no drop of tools. The gloves are the prop. This applies to all six gestures and the world-switch.

How does the player cross between worlds spatially? Can they physically walk through a portal?

Locked: Only via Scale gesture. A portal window is view-only by default. To cross physically, the player expands the portal frame using the Scale gesture (two-hand spread) to at minimum 1.6 m wide × 2 m tall — at which point the collision layer activates. The portal frame remains open until collapsed.

The world-switch gesture changes the player's current world state in-place — the environment changes around them, they don't move. Walking through a scaled portal moves the player spatially into the other world's coordinate space.

Level design implication: Modules must account for a player who arrived from either world via portal. Receiver pads must exist in both world states to avoid invisible collision issues.

Can objects from one world be left permanently in the other? What are the limits?
  • Pulled objects that are Anchored for ≥ 3 seconds fully assimilate into the new world — tagged Assimilated, persist until level or puzzle reset.
  • Objects dropped and resting on a surface for 3 seconds also assimilate — same outcome.
  • Objects that fall off the map before assimilating auto-return (existing rule, confirmed).
  • Maximum 4 assimilated objects per module at any time — performance constraint (Quest standalone) and puzzle design constraint.
How does the Fold gesture interact with physics objects already in the world? If you fold a section, do objects on that section fold with it?
  • Objects tagged WorldGeometry fold with the terrain (children of the folded section's transform).
  • Objects tagged Pullable or Assimilated do not fold — they are left floating then fall with normal physics. Intentional — creates emergent moments where folding reveals an unsupported object.
  • If the player is standing on the fold target, the gesture is blocked (glove dims, denied sound). Player must move off first.
  • Fold duration: Persists until player releases the gesture or moves > 3 m from fold seam. If player walks across then moves out of range, the fold snaps back. To cross safely: Fold → Anchor it → walk across → un-Anchor on the other side.
What is the navigation model for levels with branching paths?

Locked: Soft-linear branching. All branching paths are one of three types:

  1. Optional detour — dead-end spur with narrative reward, returns to main path.
  2. Parallel routes — two paths converge at the same module. Both completable, neither required.
  3. World-gated door — a path only accessible in one world state. Not a branch per se, but requires a world switch to open.

There are no permanent forks where a choice closes off content for the rest of the run. Echo Fold is a linear narrative — branching is spatial variation, not story branching.

Is there a pause menu? What can the player do from it?

Locked: Pause triggered by looking down at the left wrist (wrist-up + gaze down toward palm for 1 s). A diegetic holographic panel appears on the wrist. Options:

  • Resume (close fist on panel)
  • Reset puzzle (resets current module's objects to spawn, no player respawn)
  • Comfort settings (vignette %, teleport toggle, snap-turn increments)
  • Audio logs (replay collected logs from current level)
  • Quit to main menu

No save option — game autosaves at checkpoints. No chapter select until first completion (New Game+ unlock). Pause panel is always Sterile-world aesthetic regardless of current world state.

What is the main menu / title screen?

Locked: Player spawns inside a "prelude room" — a hybrid-state version of Module A1. Quiet, still, half Overgrown half Sterile. A single portal frame on the far wall shows the title ECHO FOLD through it in the other world's dressing.

Three diegetic interaction points (no floating UI):

  • A console (Sterile) — Script-trigger to start New Game
  • A journal on a plinth (Overgrown) — Script-trigger to load last save
  • A door — sealed until first completion, then chapter select

No loading screen — the prelude room loads Chapter 1 when the player interacts with the console. Fade to black (0.8 s), then 1-1 begins.

Are there collectibles beyond audio logs? What is the reward for exploration?

Locked: Two collectible types.

  • Audio logs — already established. Sterile world. Asha's scientific records.
  • Memory fragments — Overgrown world only. Small glowing objects (torn photographs, pressed flowers, a child's drawing). Proximity trigger — no gesture required. Plays a 5–10 s ambient audio memory (Asha's internal monologue, non-expository, emotional). Not subtitled by default. 3 per level, always off the critical path.

Completion reward: After collecting all memory fragments in a chapter, the prelude room gains a visual change — Overgrown world grows further into the Sterile side. By Ch5, the prelude room is 80% Overgrown. No achievement pop-ups, no percentage counters — the room changing is the signal.

What accessibility options are required?

Locked minimum set before release (in addition to teleport, snap-turn, and vignette already specified):

  • Subtitle / caption toggle — all audio: logs, memory fragments, ambient dialogue.
  • One-handed mode — all two-handed gestures have a one-handed fallback. Rotate: one hand circles object. Scale: one hand moves toward/away. Fold: one-hand pinch + hold 1 s.
  • Gesture sensitivity slider — adjusts threshold values for all gesture detection (finger curl angle, wrist rotation delta). High sensitivity for limited range of motion.
  • Ghost geometry opacity slider — increase the 15% ghost opacity up to 60% for players who struggle to read the puzzle space.
  • Puzzle hint system — after 90 s of no progress in a G-type module, gloves emit faint directional glow toward next interaction. After 180 s, diegetic audio hint plays (Asha muttering). Default ON, opt-out in settings.
What is the definition of "level complete"? What signals it to the player?

Locked: A level is complete when the last module's exit trigger is crossed. The exit trigger is always a teal portal frame at the final module's end. Crossing it:

  1. Fades to black (0.5 s)
  2. Plays a 3–4 s ambient musical sting (diegetic — from a radio or speaker in the prelude space)
  3. Fades up in the prelude room — player briefly returned here between levels
  4. A new narrative prop has appeared in the prelude room (physical object from the level just completed)
  5. After 8 s (or on player gesture), fade to black and load next level

The prelude room between levels is a breath and reflection moment — not a hub to navigate. Also serves as the natural loading screen (loads next level behind the fade).

§ 07

Engine Clarification — Unity vs Godot ⚠ Conflict

GDD Part 1 specifies Godot 4.x. GDD Part 2 specifies Unity URP. These conflict. One must be locked before any development begins.
🌿 Godot 4.x
  • Quest VRgodot-openxr-vendors (community, active)
  • Hand trackingOpenXR via plugin
  • Custom shadersGDShader — simpler syntax, less documentation
  • Render texturesSupported via SubViewport
  • DistributionExport to web free
  • VR communitySmaller, but Echo Fold-scale projects are feasible
🔬 Unity URP
  • Quest VRMeta XR SDK — first-party, more documentation
  • Hand trackingMeta Hand SDK — more mature samples
  • Custom shadersShaderGraph + HLSL — more tutorials, CC0 examples
  • Render texturesSupported via Render Texture + Camera
  • DistributionBuild pipeline free, asset store dependency risk
  • VR communityLarger, more Stack Overflow answers

Recommendation: If you have existing Unity experience, use Unity URP — the Meta XR SDK hand tracking samples will save weeks. If starting from zero, Godot has lower initial overhead. Pick one and propagate through the entire GDD.

The platform material map in GDD v2 uses Unity URP naming conventions. If choosing Godot, these map directly to Godot's StandardMaterial3D params with identical names — no capability is lost either way.

§ 08

Missing Technical Specs

Module Footprint Standard

All modules must declare a standard footprint so the level assembly system can validate no overlap:

  • Width: 8 m (X axis). All walkable surfaces must fit within ±4 m of module root X.
  • Height: 6 m (Y) for A/B/C/D/E/F modules. 20 m for H (vertical). 12 m for G (puzzle room).
  • Depth: Variable. Declared as exported var module_depth (float, metres). Level assembly reads this to auto-position the next module.

Scene Naming Convention

Module_[Type][Variant]-[World].tscn

Examples:
  Module_A1-S.tscn
  Module_G2.tscn          ← world-neutral modules
  Module_H3-S.tscn
  Module_J2.tscn
  Module_X4.tscn
